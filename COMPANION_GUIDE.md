# LaraDeck Laravel companion

Open **Laravel companion** in the sidebar. Extract the release's application executable and `laradeck-runner.exe` into the same directory, then launch the application named in the release README. Close older LaraDeck windows before launching the new build.

Existing Herd projects, HTTPS configuration, project files and database data are preserved. The app does not automatically install packages, migrate databases or start project services. A stable WebView profile selection preserves local audit citations across executable names by reusing an existing profile in place. No browser credentials or profile files are copied.

| Tool | How to use it |
| --- | --- |
| Workspace | Refresh health to see every discovered project's static readiness, owned processes and audit coverage. Expand readiness to see unchecked items; package presence does not prove an endpoint works. |
| Startup | Load or save a named profile, choose Vite/queue/scheduler/services, then start it. Vite profiles require a direct `vite` dev script and use the selected port with strict-port behavior. Starting workers/scheduler executes real application jobs/tasks. Existing services are not adopted. Stop waits for owned project processes; force stop is explicit. |
| Diagnostics | Inspect runtime and Composer platform requirements. Preview locked Composer install, npm ci, asset build or config clear. Apply only after typing the project name. Clockwork installation/repair uses the existing dependency manager. npm ci requires package-lock.json. |
| Performance | Refresh Clockwork in Telemetry, choose a request, pin a baseline, then compare another capture of the same method/path. Timing and normalized query-count differences are observations, not a controlled benchmark. Memory stays unavailable when Clockwork does not supply it. |
| Migrations | Inspect target and applied/pending migrations, preview SQL, save/compare schema, then explicitly apply pending migrations or roll back one migration. Preview prevents SQL execution on the confirmed default connection, and execution guards reject queries to other Laravel-managed connections. Migration PHP can still have external/non-SQL side effects; separately review workflows that deliberately use multiple databases. Migration execution requires Laravel connection events and beforeExecuting support. Schema inspection is bounded to 200 tables; incomplete schemas cannot produce a removal comparison. |
| Audit history | New completed audits are retained (latest 20). Compare new, recurring and resolved/not-observed findings. Resolution requires matching configuration fingerprints and matching completed owner coverage; otherwise missing findings remain not observed. Source-based finding fingerprints preserve citations across line movement and require review after surrounding source changes. Existing line-based citations migrate when a fingerprint first appears. |
| Timeline | Inspect queries and exception count belonging to an actual Clockwork request. Optional Telescope batch inspection shows recorded associations for jobs/events/mail/HTTP/etc. No cross-process relationship is invented. Sensitive payloads and SQL bindings are not returned by the Telescope adapter. |
| Cache & sessions | Read bounded file/database/PhpRedis pages. Values start masked; reveal one selected value, or confirm deletion of one entry. File cache keys are hashes. Redis requires a named loopback connection and a nonempty project prefix; cluster/Predis/cookie/array stores are explicitly unsupported. A SCAN page can be empty while its cursor remains nonzero. File browsing inspects at most 10,000 files per call. |
| Route tests | Load routes with middleware/parameters, replace URL placeholders, supply headers/body, and explicitly send a request to the selected project origin. Generate an editable Pest/PHPUnit draft from JSON request data; credential fields are replaced with test-fixture placeholders. Save a new tests/Feature/*Test.php file without overwriting existing tests. Auth/CSRF setup must be arranged in the test. |
| Snapshots | Inspect the database target. Create a local snapshot; type the exact connection/database label to restore. Restoration checks project/connection identity and checksum and creates a recovery snapshot first. Stop workers and application writes before restoring. Native restores may partially apply on failure; the recovery artifact is retained. |
| Integrations | Detect Telescope/Pulse, explicitly install their development package, preview asset/provider/config publishing, then inspect pending migrations separately. Dashboard opening reads the configured path and checks route registration. Review Telescope's local-only provider registration before committing or deploying project setup. |

Runtime tools require a trusted project with installed dependencies and `APP_ENV=local` or `testing`. Database tools only accept loopback hosts (or local SQLite paths). They are development tools, not remote/production administration tools.

SQLite snapshots require PHP's `sqlite3` extension and an on-disk database. MySQL/MariaDB needs `mysqldump.exe` for backup and `mysql.exe` for restore. PostgreSQL needs `pg_dump.exe`/`pg_restore.exe`. Use compatible native client versions in PATH or supply full executable paths. Restore can require a separate backup executable for its recovery snapshot. Passwords are passed through child-process environment variables, never command arguments or logs. Snapshot files contain database data; protect and retain them accordingly.

Companion artifacts live under `%APPDATA%/HerdWorkbench/companion/<project-id>`. Browser-profile selection is recorded in `%APPDATA%/HerdWorkbench/webview-profile.json`.

Windows console shutdown cannot guarantee that a Laravel queue worker finishes its current job. Stop workers while idle or allow jobs to finish; force stop can interrupt work. The app does not send a project-wide queue:restart signal that would also stop unowned workers.
# Composer and npm health

Open **Laravel companion → Packages** for the selected trusted project. **Refresh inventory** reads manifests, locks and installed metadata without executing project code. **Run local checks** validates Composer schema/lock consistency and locked PHP/extension requirements, compares vendor metadata with the lock, checks npm root lock declarations and runs `npm ls --depth=0`. Composer plugins and package scripts are disabled; local checks use offline mode.

**Check updates & advisories** asks for confirmation before querying the project's configured registries. Dependency names and versions are sent; project source code is not uploaded. It runs Composer locked-package outdated/audit checks and npm outdated/audit checks. It never runs install, update or audit fix. Reports follow package-manager registry/advisory policies; ignored advisories and unknown vulnerabilities are outside the result. Unreachable repositories, malformed output and failed commands remain incomplete, including Composer's successful exit with partial registry coverage.

Composer inventory lists all locked packages; npm inventory lists root direct runtime/dev/optional/peer dependencies. npm outdated also follows configured workspaces; npm audit checks the lockfile. Root declaration equality is not exhaustive workspace or resolution validation. Yarn, pnpm and Bun projects are not silently scanned with npm. npm v1 lockfiles do not receive the root-declaration consistency check. Missing dev/optional packages can be intentional. Installed metadata comparisons do not verify package file integrity.

Workspace Composer/npm badges show the last result. They require a recheck after tracked manifests, lockfiles or installation metadata change, or after 24 hours. High/critical advisories are red; other findings are yellow; incomplete/unrun checks are gray. Package latest-version badges are red for newer major versions and yellow for newer minor/patch versions; these indicate upgrade size, not security support.
